🎯 **What:** The API key was previously being saved persistently to the browser's localStorage in plain text alongside other configuration values.
⚠️ **Risk:** If a malicious script (XSS) gains execution in the user's browser, it could access localStorage and exfiltrate the plain text API key. It also leaves the key persistently on the disk, making it available to anyone using the same machine/browser even after the session ends.
🛡️ **Solution:** Modified the `saveConfig` and `loadPersistedData` functions. Now, a copy of the configuration object is created and the `apiKey` is removed before saving to `localStorage`. The `apiKey` is instead saved only to `sessionStorage`, which clears when the browser/tab is closed. Also added logic to automatically clear any legacy `apiKey` from `localStorage` on load.
